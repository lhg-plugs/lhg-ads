# lhg-ads-tracking：数据追踪与口径方法论

> 目标：解决投放中最常见的源头问题——"数据对不上"。链接没 UTM、指标没口径，复盘就是玄学。
> 核心纪律：**先定口径，再看数据；口径不同，数字不可比。**

## 1. 何时使用

- 投放上线前 → 按第 3.1 节给每条链接加 UTM，按第 3.3 节输出口径文档
- 复盘时发现"平台数据和后台对不上" → 用第 3.2 节排查归因差异
- 拿到一份别人的复盘报告想验证 → 对照第 5 节质检门检查口径

## 2. 输入与输出

**输入：**

| 输入项 | 说明 |
|---|---|
| 投放链接清单 | 每条对外投放的落地页 URL |
| 渠道与广告组命名 | 用于 utm_campaign 的命名体系 |
| 转化定义 | 什么算一次转化（下单/加购/留资/点击） |

**输出：** 带完整 UTM 的链接清单 + 「指标口径」文档章节（可直接贴进复盘报告）。

## 3. 分步方法论

### 3.1 UTM 参数规范

每条投放链接必须带三个参数（缺一不可）：

| 参数 | 含义 | 命名规范 | 示例值 |
|---|---|---|---|
| utm_source | 流量来源 | 平台英文名小写 | xiaohongshu |
| utm_medium | 媒介类型 | cpc / cpm / koc / feed | cpc |
| utm_campaign | 广告系列 | 产品_日期_版本 | newtea_1011_v1 |

完整示例：
`https://shop.example.com/buy?utm_source=xiaohongshu&utm_medium=cpc&utm_campaign=newtea_1011_v1`

**命名铁律：**

- 全小写、下划线分隔，不许用中文（部分系统编码会乱）
- utm_campaign 必须能反查到具体的投放计划文档（日期+版本）
- 同一产品不同渠道，utm_source 必须不同；同一渠道不同素材，用 utm_content 区分

### 3.2 归因窗口：数据对不上的头号原因

平台后台的"转化数"和你自己后台的"订单数"对不上，90% 是归因窗口不同：

- **点击归因窗口**：用户点击广告后多少天内转化算广告的功劳（常见 1 天 / 7 天）
- **展示归因窗口**：用户只看到没点击，多少天内转化算广告的功劳（常见 1 天）

**规则：** 同一次复盘里，所有渠道必须用同一归因窗口对比；跨平台对比时，先换算到同一窗口再下结论。口径文档里必须写清窗口（见 3.3）。

### 3.3 核心指标口径定义模板

复盘文档的「指标口径」章节按此模板写，一个指标一行：

| 指标 | 定义公式 | 归因窗口 | 数据来源 |
|---|---|---|---|
| CTR（点击率） | 点击量 / 展示量 | 展示当日 | 平台后台 |
| CVR（转化率） | 转化数 / 点击量 | 点击后 7 天 | 平台后台 |
| CPC（平均点击成本） | 广告花费 / 点击量 | — | 平台后台 |
| CPA（获客成本） | 广告花费 / 转化数 | 点击后 7 天 | 平台后台 |
| ROAS（投产比） | 广告带来成交额 / 广告花费 | 点击后 7 天 | 平台后台+订单系统 |

**注意：**「转化」在不同投放中定义不同（下单/加购/留资），必须在口径表第一行写清"本计划转化定义 = X"。转化定义变了，历史数据全部不可比。

### 3.4 上线前追踪检查清单

- [ ] 每条投放链接都带 utm_source/medium/campaign
- [ ] utm_campaign 命名可反查到投放计划文档
- [ ] 转化定义已写入口径文档
- [ ] 归因窗口已确定并写入口径文档
- [ ] 落地页能正常接收并记录 UTM 参数（技术联调确认）

### 3.5 归因差异排查表

| 现象 | 可能原因 | 排查动作 |
|---|---|---|
| 平台转化数 > 自家订单数 | 归因窗口长 / 重复计算加购 | 对齐归因窗口，以订单系统为准 |
| 平台转化数 < 自家订单数 | 部分转化未回传 / 归因窗口短 | 检查回传链路是否丢数据 |
| A 渠道 ROAS 骤降 | utm_campaign 被改名，数据断流 | 检查命名是否有人手动改过 |
| 自然流量突然大涨 | 裸链被转发，UTM 丢失 | 排查是否有未带参链接在传播 |

**最终口径：** 花出去的钱以平台为准，赚回来的钱以自家订单系统为准。两个数对不上时，相信订单系统。

### 3.6 UTM 命名示例库

直接抄格式，替换括号内容：

| 场景 | utm_source | utm_medium | utm_campaign |
|---|---|---|---|
| 小红书信息流-新品 | xiaohongshu | feed | (产品)_launch_(日期)_v1 |
| 抖音短视频-种草 | douyin | video | (产品)_seeding_(日期)_v1 |
| 百度搜索-品牌词 | baidu | cpc | (产品)_brand_(日期)_v1 |
| 公众号文末-老品 | wechat | article | (产品)_content_(日期)_v1 |
| KOC 探店-单条 | koc_(博主名) | video | (产品)_koc_(日期) |

**反例：** `utm_campaign=test`、`utm_campaign=final_final2`——三个月后没人知道这是什么，数据直接作废。

### 3.7 新人最常问的 5 个问题

1. **Q：历史链接没带 UTM，能补吗？** A：补不了，历史数据已丢失。从今天起所有新链接带参。
2. **Q：utm_content 什么时候用？** A：同一广告系列下区分不同素材/文案版本时用。
3. **Q：短链接会丢 UTM 吗？** A：正规短链接服务会保留参数，自建跳转要测试验证。
4. **Q：APP 内投放怎么带 UTM？** A：用渠道包或归因 SDK（如示例口径中的第三方归因工具），原理相同：来源可标识。
5. **Q：口径文档多久更新一次？** A：转化定义或归因窗口变了就更新，版本号 +1，旧版本存档。
6. **Q：小预算有必要搞这么复杂吗？** A：UTM 三分钟配好，口径表十分钟写完；数据乱了再返工，代价是十倍。

## 4. 反模式（这些做法一定错）

1. **链接裸奔上线**：没 UTM 的链接花出去的钱，复盘时全算成"自然流量"。
2. **utm_campaign 随手写**："test1""final2"这种命名，三个月后没人知道是什么。
3. **拿平台 A 的 7 天归因和平台 B 的 1 天归因直接比 ROAS**：口径不同，比较无意义。
4. **中途改转化定义**：上周转化=加购，这周转化=下单，然后说"转化率暴跌"——口径变了，不是业务变了。
5. **只看平台后台不看自己订单系统**：平台归因偏乐观，最终以实际成交额为准。

## 5. 自检与反馈

**质检门（投放上线前 / 复盘发布前逐项打勾）：**

- [ ] 所有投放链接带完整 UTM（跑审计脚本 ADS-UTM-001）
- [ ] 口径文档包含：转化定义、归因窗口、每个指标的定义公式与数据来源
- [ ] 复盘报告引用了口径文档（跑审计脚本 ADS-REV-001）
- [ ] 跨渠道对比使用了同一归因窗口

**标准冒烟用例：** 用 `fixtures/ads-bad/campaign.md` 跑审计脚本，应命中 ADS-UTM-001 / ADS-REV-001；用 `fixtures/ads-good/campaign.md` 跑，应零 warning（UTM 与口径齐全）。
